## 0. TL;DR（10 条结论）

1. **没有 navigation-compose**：导航是 MainActivity 里 3 个 `rememberSaveable` 字符串/布尔组成的手写状态机（`MainActivity.kt:168-174`、`:188-255`），底部 Tab 也是手写 56dp Row。
2. 课表页结构固定为「矮顶栏 + 日期行 + HorizontalPager（每页一周）+ 不可滚动网格」；课程块用自定义 `Modifier.layout` 在 12 小节坐标系里绝对定位，13 节被 clamp（`sch/ScheduleScreen.kt:590-724`、`:815-825`、`main/model/SectionMap.kt:15`）。
3. 「用户选周」与「重进定位当前周」不是简单状态：ViewModel 用 `selectedWeek: MutableStateFlow<Int?>`（null=未选）+ `AppSession.epoch` + 镜像 `sessionEpoch` 三者推进（`sch/ScheduleViewModel.kt:74-123`、`:163-203`）；Pager 侧再有 initialPage/`drop(1)`/`loaded` 三道闸（`sch/ScheduleScreen.kt:204-240`，commit `4f47117`→`4dc6184`→`008571a`）。
4. 状态层是「一个 `StateFlow<ScheduleUiState>` + 6 条独立设置 StateFlow」，全部 `collectAsStateWithLifecycle`；局部 UI 用 remember/rememberSaveable + 2 个自定义 Saver（课程详情、编辑草稿之外的瞬时态）。
5. 主题：`dynamicColor` **恒开**（`main/ui/theme/Theme.kt:46`，minSdk 34 必然走动态取色），课程色板是固定浅色（`main/ui/theme/CourseColors.kt:9-20`）；两套手写整屏渐变只铺课表 Tab。
6. **系统栏图标是手工按 app 主题反色的**，不看系统 uiMode（`MainActivity.kt:176-186`）；全屏同步页会通过回调切反色（`:180` + `main/ui/sync/UnifiedSyncScreen.kt:94/101`）。
7. 无障碍是「重点控件做了、网格没做」：Tab/色块/开关有 Role+选中语义，但空白网格格、课程卡、图钉缺 label/onClickLabel（`sch/ScheduleScreen.kt:646-674`、`:760`、`:793-807`）。
8. 性能第一热点：`rememberNow()` 每分钟触发**整个 ScheduleScreen 重组**，并重跑 `CourseMerger.mergeSameSlot` + `NextClass.resolve`（`sch/ScheduleScreen.kt:157/193-203`、`main/ui/common/Now.kt:30-48`）；另外 ScheduleScreen 订阅了 3 条从未使用的提醒 Flow（`:134-138`）。
9. 所有 UI 文案硬编码中文，`res/values/strings.xml` 只有 `app_name`（`:2`），`WEEKDAY_NAMES` 重复 3 份；因此当前无多语言、`supportsRtl` 名存实亡。
10. 文件过大：ScheduleScreen 893 行 / SemesterSettingsPage 543 / CourseEditDialog 529 / ScheduleViewModel 270；拆分点见 §7。

### 1.3 返回键行为

- 课表/教务/我的三个 Tab **都没有 BackHandler**（全仓仅两处：`sch/SemesterSettingsPage.kt:138`、`main/ui/sync/UnifiedSyncScreen.kt:93`）⇒ 在「教务」「我的」按返回直接退出 Activity，不会回课表（见 §6 P1）。
- 弹层：`ModalBottomSheet`（详情/无固定时间）与 `AlertDialog`（编辑）走各自 Dialog 窗口的返回处理，会关弹层。
- 无「再按一次退出」提示；无 `android:enableOnBackInvokedCallback` 显式配置（targetSdk 37 默认启用预测性返回，Compose BackHandler 可用）。

### 1.4 系统栏 / edge-to-edge / insets

- `enableEdgeToEdge()` 在 `onCreate`（`MainActivity.kt:143`）；页面背景靠外层 Box 铺渐变（`:200-208`），`Scaffold.contentWindowInsets = 0`（`:212`）⇒ 各页自己处理状态栏。
- 课表顶栏 `statusBarsPadding()` + 58dp 自定义矮栏（`sch/ScheduleScreen.kt:251-257`），底部 Tab `navigationBarsPadding()`（`MainActivity.kt:221/233`）；学期设置页同样 `statusBarsPadding`/`navigationBarsPadding`/`imePadding`（`sch/SemesterSettingsPage.kt:176/194/195`）。
- 图标明暗：`darkIcons = if (showSync && syncLightPage) true else !darkTheme`，`SideEffect` 同时设置 status/nav bar（`MainActivity.kt:180-186`）。手工设置的**真实理由**是 app 主题（跟随系统/浅/深）可与系统 uiMode 分歧；但 `:176-179` 注释里「Theme.Material.Light 恒为 notnight」的说法不准确（uiMode 由系统配置决定，与该 XML 父主题无关），重构时别照抄结论。
- 未关闭导航栏对比度强制（无 `isNavigationBarContrastEnforced=false`）⇒ 三键导航机型可能在渐变底部叠一层暗 scrim（§6 P3）。
- 键盘：Activity `windowSoftInputMode=adjustResize`（`AndroidManifest.xml:37`）；课表页无 `imePadding`（课表页无输入框），编辑弹窗/学期设置各自处理（§6 P2 关于弹窗可滚动性）。

## 2. ScheduleScreen 渲染机制

### 2.1 组合树（`sch/ScheduleScreen.kt:243-471`）

`Scaffold(透明, `:243-245`)` → `topBar`(`:246-334`) / `FAB`(`:335-343`) / `Column`(`:345`) → 空态或 [`DateRow`(`:358-364`) + 假期条(`:365-374`) + `HorizontalPager`(`:375-401`) → 每页 `WeekGrid`(`:379-400`)`]` → 三个弹层(`:406-470`)。
`DateRow` 在 Pager **外面**，只跟随 `selectedWeek`；Pager 每页自己算 `daySchedules`（`:384-386`）但列集合 `visibleDays` 是全局的（`:162-171`）。

### 2.2 Pager ↔ 周次状态同步（最容易踩坑的地方）

ViewModel 侧：
- `selectedWeek` 私有 `MutableStateFlow<Int?>`，**null 的语义是「未选/需重新定位」**，不能用 1 当哨兵（`sch/ScheduleViewModel.kt:74-85` 注释解释了「点设置开关课表跳回本周」的旧 bug）。
- `AppSession.epoch`：`onStop`（配置变更除外）自增（`MainActivity.kt:131-139`、`main/data/pref/AppSession.kt:20-31`，不落盘）。
- `sessionEpoch` 必须作为 uiState 的 combine 输入：`selectedWeek` 等值写 null 不发射，只靠它才能强制重算「今天是第几周」（`sch/ScheduleViewModel.kt:87-96`）。
- `init` 里收集 epoch：`selectedWeek=null` + `sessionEpoch=epoch`（`:163-179`）；uiState 解析 `week ?: WeekResolver.defaultWeek(...)` 并 `coerceIn` 兜底（`:98-123`，兜底理由 `:112-114`）。
- `todayHoliday` 也在 combine 里用 `LocalDate.now()` 求值（`:117`）⇒ **uiState 没有时钟输入，跨午夜不会自动刷新**（§6 P3）。

UI 侧（四条规则）：
1. `initialPage = state.selectedWeek - 1`，**故意不用 currentWeek**：旋转后不要把正在看第 5 周的用户甩回第 8 周（`sch/ScheduleScreen.kt:204-210`）。
2. 用户滑动 → `snapshotFlow{currentPage}.drop(1)` 回写 `selectWeek(page+1)`；丢首帧是因为首帧是初始页/程序滚动的结果（`:213-226`）。
3. **`state.loaded` 门闩**：数据未加载完既不回写、也不滚动——进程被回收后 Pager 会恢复旧页，而首帧 uiState 还是默认第 1 周；若先把这次「程序性滚动」当用户选周写回，定位就永久失效（`:218-225`、`:234-239`，修复 commit `008571a`，diff 仅 13 行）。
4. `selectedWeek` 变化（含 epoch 重定位）→ `scrollToPage`，**瞬间落位不用动画**：重进 App 应该第一眼本周（`:231-240`）。

时序对照：

| 场景 | 行为 | 代码 |
|---|---|---|
| 冷启动 | 首帧默认状态(loaded=false)→数据到→定位当前周（第1周会先闪一帧，§6 P2） | `:204-240`、VM `:98-123` |
| 进程被回收后重建 | Pager 恢复旧页 + loaded 门闩 → 定位当前周且不回写 | `:213-240` |
| 退后台再进 | `onStop` epoch+1 → VM 清空 selectedWeek → 重定位 | `MainActivity.kt:131-139`、VM `:172-179` |
| App 内切 Tab / 旋转 | epoch 不变，用户选周保留；旋转靠 initialPage 保页 | `AppSession.kt:7-19`、`:204-210` |
| 周次下拉 | `animateScrollToPage` → settle → 回写 selectedWeek | `:284-315`（`:311`） |
| 回到本周按钮 | 仅当 `currentWeek!=null && selectedWeek!=currentWeek` 显示 | `:317-323` |

### 2.4 网格测量与滚动

- 无任何垂直滚动：`WeekGrid` 根是 `Row(fillMaxSize)`，底部留 `FAB_CLEARANCE=56dp`（`:110`、`:611`），注释明确「网格不可滚动，FAB 压住的最后一节看不回来」。所以高度被屏幕锁死，靠 `weight(range.count())` 按小节数分配 6 大节（`:614-630`、`:646-674`），列宽靠 `weight(1f)`（`:644`、`:700-702`）。
- 课程块定位：`Modifier.coursePosition` 在 `layout{}` 里读父约束 `maxHeight/12` 得单位高，再 `measure` 固定高、`place` 到 `(start-1)*unit`（`:815-825`）；不能换成 `fillMaxHeight`+offset（注释 `:812-814`）。
- 滚动只有横向 Pager（`:375-401`）；弹层内是独立 `LazyColumn`（`:852-890`，并为了修「弹层抽搐」固定 Expanded 锚点 + 关回弹，`:839-851`）。**没有 NestedScroll**，因此也没有嵌套滚动冲突——代价是网格永远不滚动。
- 对齐：日期行每列 `padding(horizontal=1.dp)`（`:528`） vs 网格日列无 padding（`:644`），理论上有 1~2dp 偏差，靠卡片 `padding(1.dp)`（`:751`）掩盖；节次列 `SECTION_COL_WIDTH=36.dp`（`:586`）两侧一致。
- 测量边界：非周一开学日期会被 `weekMonday` 归一化到周一（`WeekResolver.kt:86-110`），日期行与「今天」胶囊因此依赖该实现，不要另写一份日期推算。

### 3.2 mutableStateOf vs StateFlow

- 跨页面/跨重建的持久状态 → `StateFlow`（VM）；Composable 内瞬时 UI 状态 → `mutableStateOf`/`rememberSaveable`（`sch/ScheduleScreen.kt:141-157`）。
- 编辑对话框的时段模型 `SessionState` 是普通 class + 3 个 `mutableStateOf` 字段（`sch/CourseEditDialog.kt:77-84`），列表 `toMutableStateList()`（`:136-147`）；这样每个 `SessionEditor` 只读自己那段状态，点 chip 只重组该时段（注释 `:282-284`）。
- 弹层数据的 JSON Saver 用 kotlinx.serialization：课程详情（`sch/ScheduleScreen.kt:97-100`）、成绩详情（`main/ui/grades/GradesScreen.kt:114`）。

### 3.4 编辑/详情交互回路

1. 点课程卡 → `detailCourse`（saveable）→ `CourseDetailSheet`（`sch/ScheduleScreen.kt:406-433`、`sch/CourseDetailSheet.kt:37-116`）。
2. 编辑 → `groupOf(name+source)` 取全部存储行（`:179-180`）→ `editCourseGroup` + `showEditDialog`（`:414-419`）；隐藏/删除同样作用于整组（`:424-431`）——只改一行会出现「点了隐藏没反应」。
3. 长按空白格 → `pendingSlot`（+ 图标出现 `:658-671`）→ **再点同一格** → `prefillSession` + 打开编辑框（`:391-398`）；点其他格只取消。

## 9. 建议的接手顺序

1. 低风险高收益三件套：Tab 返回键、空白格语义、课程卡滚动/详情弹层可滚动。
2. 性能：`now` 下沉 + 删死订阅 → 开 Compose compiler metrics 验证稳定性 → 再决定 `@Immutable`/持久集合改造。
3. 结构拆分（纯移动，不改行为），同时抽 `strings.xml` 与统一星期/尺寸常量。
4. 视觉统一：暗色课程色板、导航栏 contrast、splash/冷启动、空态主按钮；与产品确认动态取色是否保留。
5. 补 UI 测试（Pager 定位、编辑保存、假期/补课渲染、无障碍语义）后，再动 §2.2 这类高耦合同步逻辑。
